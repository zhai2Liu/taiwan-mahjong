## 2. 電腦吃碰門檻（行為變更）

### 問題

現行策略在吃碰後的合法捨牌牌效「較好」時就叫牌，包含距離聽牌步數相同、只是有效進張變多的情況。固定種子 6 將實測，平均每局吃碰明槓約 **7.7 次**，146 局流局 **0 次**，0 台胡占 **26.7%**。

### 規則（`src/ai.ts` 的 `worthCalling`）

只套用在 CHI／PON；胡牌與槓的判斷不變。以下三條依序判斷：

1. 叫牌後的最佳合法捨牌**沒有讓離聽牌步數減少**，就不叫。只是有效進張變多也不叫。
2. 已有吃、碰或明槓（只有暗槓不算），就照舊叫。
3. 仍然門清時，只在以下兩種情況叫：
   - 叫牌後已在**一向聽以內**；
   - **碰**三元牌，或碰自己的門風、圈風（碰後即有台）。

被門檻擋下的選項不參與比較，此時「過」會勝出。如果呼叫端只交出吃碰選項、沒有「過」，就不套用門檻，避免沒有合法動作可回傳。

門檻只讀 Observation 已有的欄位：`self.melds`、`lastDiscard`、`roundWind`、`seat`、`dealer`，資訊邊界不變。決策紀錄、亂數狀態的推進方式與回傳格式都不變。

### 實測（同一組種子，電腦互打，不代表真人牌局）

指令：`npm run stats:ai -- 6 1000`（種子 1000–1005、每將 16 次移莊）。

| 指標 | 調整前 `09ee410` | 調整後 |
|---|---|---|
| 局數 | 146 | 140 |
| 每局吃碰明槓 | 7.664 | **3.893** |
| 　吃／碰 | 3.774／3.747 | 1.643／2.086 |
| 每局槓（三種合計） | 0.342 | 0.386 |
| 放槍胡／自摸／流局 | 79.5%／20.5%／0% | 75.0%／22.1%／2.9% |
| 胡牌平均台數（最高） | 1.38（5） | 1.51（6） |
| 0 台胡比例 | 26.7% | 18.4% |
| 每次電腦決策平均 | 13.59 ms | 14.36 ms |

解讀界線：

- 這些是本機電腦對電腦的結果，沒有真人基準，不能宣稱「更像人」或「更強」。
- 放槍胡仍占四分之三，因為正式 AI 仍完全沒有防守，這屬於 S6 範圍。
- 決策耗時差異在量測雜訊範圍內。既有「100 次決策 < 5 秒」測試仍通過。

### 新增測試（`test/ai.test.mjs`）

- 「AI 門清且叫牌後仍離聽牌兩步以上時不吃碰；有台字牌碰與已副露手不受此限」：
  - 門清遠手吃 2m → PASS；
  - 門清遠手碰 5z（紅中）→ PON；
  - 已碰 999s 的遠手吃 2m → CHI。

  每個情境都先斷言引擎確實提供該吃碰選項。**此測試在基準 `src/ai.ts` 上會失敗**（第一個情境基準會吃），已實測確認。
- 「AI 只拿到吃碰選項（沒有過）時仍回傳合法動作」。
- 既有「吃碰先比較合法捨牌後效率，改善才叫牌」的三個情境結果不變。

## 3. `engine.ts` 可讀性調整

`src/engine.ts` 原有 17 行超過 160 字元，調整後為 0 行。大部分只是換行，下列 **5 處**程式文字有改動，但語意等價，請逐項核對：

| 位置 | 改動 | 等價理由 |
|---|---|---|
| `canonical` | 把 `Object.entries(...).sort(...)` 抽成區域變數 `entries` | 同一運算，只是分兩行 |
| `flowerWin` | `items.push` 改成依 `mode` 選兩個完整物件 | 原本兩個欄位各自判斷同一條件，結果相同 |
| `checkFlowers` | 抽出 `count(x)` 取代三次 `s.players[x].flowers.length` | 純讀取、沒有副作用 |
| `possibleClaims` | PON 的單行 `if` 加上大括號 | 控制流程相同 |
| `applyAction` 的 `WIN` | 把 `deal ? null : lastTile` 抽成區域變數 `tile` | 只在同一分支計算一次，沒有副作用 |

驗證方式：

1. `node scripts/compare-tokens.mjs 09ee410 src/engine.ts` 只應列出上述 5 處；PON 大括號會顯示成相鄰的兩段。
2. 用同一組種子，「只改 AI」與「AI＋引擎整理」的 `stats:ai` 輸出除耗時外**逐字相同**。6 將 140 局的完整動作序列、結算台數與中途存讀檔抽查都一致，作為行為等價的佐證。
3. 引擎相關的 400 項既有測試全數通過。

`view.ts`、`learning.ts`、`training.ts` 等檔的長行多半是畫面模板，本包不動，避免擴大驗收範圍。

## 4. 相容性

- 存檔 `Session`／`GameState` 格式不變，舊存檔照常讀取。
- 電腦策略沒有版本欄位。發布後續玩舊牌局時，從下一步起會用新門檻決策，已發生的事件不變。現行規格沒有承諾跨版本重播一致，但 [HUMAN-AI-DECISION-SPEC](HUMAN-AI-DECISION-SPEC.md) 對未來人格 AI 要求「舊牌局保留舊策略」。本包刻意不預埋策略版本欄位，留待 S6 一併處理。**此點請驗收者確認可接受。**
- 決策檢討與教練分析共用 `analysis.ts`，本包沒有改動它，所以玩家看到的吃碰比較內容不變。

## 5. Codex 驗收清單

在 `outputs/taiwan-mahjong`：

```bash
npm ci
npm run check:docs                                  # 期望：0 問題
npm test                                            # 期望：402 項全過（原 400＋新增 2）
npm run build
npx playwright test                                 # 期望：58 項全過

npm run stats:ai -- 6 1000                          # 期望：除耗時外與 §2 調整後欄位相同
```

重現「調整前」欄位：

```bash
git worktree add ../tw16-base 09ee410
cp scripts/ai-stats.mjs ../tw16-base/outputs/taiwan-mahjong/scripts/
cd ../tw16-base/outputs/taiwan-mahjong && npm ci && npm run check && node scripts/ai-stats.mjs 6 1000
```

逐項核對：

- [ ] `worthCalling` 只讀 Observation 公開欄位與自家牌，不讀 `GameState`。
- [ ] 門清判斷：只有暗槓時仍視為門清。
- [ ] 吃碰被擋下時，「過」一定在候選中（引擎在回應窗口必附 PASS）。
- [ ] `compare-tokens` 的結果與 §3 表格一致。
- [ ] 確認 §4 的跨版本續玩處理可接受。
